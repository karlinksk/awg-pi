# AWG Pi Gateway v1.3.0 — реализованная система

Сверено с кодом опубликованного тега v1.3.0:
`5b1a8b802ce09a27c51f4e284f1a13207059a48e`.
Описание реализации не заменяет аппаратные доказательства:
[реестр приёмки](RELEASE-ACCEPTANCE-MATRIX-v1.3.0.md).

## Режимы и транспорт

Selective классифицирует выбранные VPN-направления через dnsmasq/nftset,
ручные домены и OpenCCK, с учётом списка клиентов. Остальное идёт DIRECT.
Ручные DIRECT-домены имеют приоритет над пересекающимися VPN/OpenCCK-доменами
и поддоменами. При отказе активного транспорта действует FAIL-OPEN.

Transit принимает выбранный MikroTik трафик, проверяет допустимый источник
и MAC доверенного роутера и передаёт его только в VPN.
Без рабочего транспорта — FAIL-CLOSED/LOCKDOWN.
Списки Selective сохраняются, но Transit не классифицируют.
Настройка RouterOS выполняется отдельно.

AWG использует awg0, Mihomo — mihomo0. Xray-нода использует путь
Mihomo TUN → локальный SOCKS Xray → сервер; отдельного Xray TUN нет.
Основной маршрут, DNS, управление и endpoints туннелей сохраняют свои
независимые пути. Связь Pi с MikroTik не доказывает SSTP.
IPv4 TCP SYN MSS ограничивается по MTU активного VPN-маршрута.

## Два независимых уровня политики

| Уровень | В рабочем меню |
| --- | --- |
| Транспорт AWG/Mihomo | MANUAL, FIXED основной/резервный, AUTO с заданным порядком |
| Узлы Mihomo/Xray | MANUAL, AUTO, отдельный переключатель Xray AUTO |

MANUAL транспорта не выключает отдельно разрешённый AUTO узлов.
FIXED транспорта сохранён; редактор FIXED-цепочки узлов удалён из рабочего
меню. AUTO сохраняет здоровый разрешённый канал, переключается после
повторных отказов и не оптимизирует скорость. Здоровый AWG остаётся выбранным
до ручной смены или подтверждённого отказа.

AUTO узлов использует штатную сетевую оценку Mihomo fixed-Selector для
текущей ноды и кандидатов. Ошибка инфраструктуры/контроллера отличается
от отрицательной сетевой оценки. Сначала рассматриваются разрешённые
нативные узлы текущего provider, затем разрешённые Xray.
Переход к рабочему AWG зависит также от политики транспорта.

Xray AUTO выключен на чистой установке. Включение требует AUTO узлов,
нужных компонентов и настроенного резервного AWG, с проверками безопасности.
Выключение Xray AUTO не прерывает немедленно уже выбранную Xray-ноду.

Ручная активация проверяет профиль, локальную службу/TUN, маршруты
и безопасность переключения, без допуска по ChatGPT/OpenAI/YouTube.
Сетевой тест движка не доказывает работу LAN-клиента или конкретного сайта.

Исправление f00c93e ограничивает начальную AWG handshake grace первыми
120 секундами монотонного uptime при активной службе и существующем
интерфейсе. Оно не отменяет FAIL-CLOSED или отказ реально исчезнувшего TUN.

## Подписки и единый список узлов

AWG: импорт файла/текста, проверка, замена и откат.
Mihomo: URL, файл или текст — YAML, VLESS URI, Base64 VLESS.
Загрузка AUTO пробует DIRECT, затем доступные настроенные транспорты;
для одной загрузки канал можно выбрать вручную. Подготовленный provider
применяется с проверками, ошибка не должна уничтожать рабочий кэш.

Единый список строится из текущего provider, без фиксированного числа
или постоянных индексов. Он показывает движок и состояния проверок.
Есть фильтры региона (все страны/подтверждённая Европа) и протокола
(все/VLESS/Trojan/Hysteria2/Shadowsocks/VMess), статистика и обновление
результатов. Смена фильтра сама по себе не переключает VPN.

Ручной выбор — **Mihomo → Точка выхода Mihomo / Xray**.
Если активен AWG, сначала явно выберите транспорт Mihomo.
Просмотр каталога не вытесняет здоровый AWG.

[Совместимость Xray](XRAY-VLESS-ADAPTER.md):
REALITY XHTTP, REALITY gRPC и поддерживаемый TLS gRPC.
Это ограниченный TCP outbound, не универсальная поддержка всех VLESS/UDP.

## Меню, обслуживание и дополнительные службы

Главное меню: состояние; VPN-маршрутизация; VPN-сервисы/домены;
DIRECT-исключения; клиенты; диагностика; обновления; журналы; система.
Вид учитывает Selective/Transit.
В системе: reboot/poweroff, согласование LAN-конфигурации, DNS, режим,
часовой пояс, дневной/месячный трафик AWG/Mihomo, DC, Telegram и оформление.
`~/.no-awg-menu` отключает автозапуск меню для соответствующего пользователя.

Hot Pool/READY, service eligibility и редактор FIXED-цепочки узлов
не являются функциями упрощённого рабочего меню. Старые helpers, CLI-ветви,
подписи и сохранённые настройки не означают возвращение этих функций.
Штатные зависимости, включая прежние media-компоненты, могут оставаться
в установщике; они не превращают video decode в release gate.

Обновления проверяют AWG Pi Gateway, AmneziaWG и соответствие Mihomo
закреплённой поддерживаемой сборке с SHA256.
Для Mihomo это проверка/восстановление, а не произвольный latest.
Профили, DNS, режим и конфигурация имеют свои проверки и откат;
полный образ носителя — [отдельная операция](BACKUP-RESTORE.md).

[Telegram](AWG-NOTIFY.md): привязка бота/чата, тест, общий переключатель,
типы событий, очередь и повторные попытки. Категории: VPN_LOST,
VPN_RESTORED, BOOT, DAILY_REPORT, NODE_SWITCH, TRANSPORT_SWITCH.
Первые четыре выбраны по умолчанию, последние две выключены.
Доставка после чистой установки выключена; категория не включает доставку.
Сводка — 09:00 по поясу Pi. Наличие hook/галочки не доказывает доставку
на каждом пути. sent/pending не заменяет подтверждение получателя.

[Desktop Commander](DESKTOP-COMMANDER.md): необязательный удалённый агент,
явная авторизация, обычный пользователь, persistent systemd-служба.
Отказ DC не должен останавливать шлюз.

## Установка и команды

[Пошаговая установка/обновление](CLEAN-INSTALL-v1.3.0-CANDIDATE.md).
Новая установка: Selective + unconfigured, движки подготовлены,
порядок транспорта AUTO Mihomo → AWG, но без профилей VPN не работает.
Обновление сохраняет явные настройки. Xray AUTO и Telegram включаются отдельно.

```bash
sudo awg-menu
sudo awg-route status
sudo awg-route mode status
sudo awg-transport get
sudo awg-selection status
sudo awg-mihomo-node-policy status
sudo awg-mihomo-node-policy xray-auto status
sudo awg-route dns status
sudo awg-route diagnostics
sudo awg-update status
sudo awg-notify status
```

## Ограничения и приёмка

Цель — Pi 4 / Debian 13 ARM64, IPv4; IPv6 policy routing не реализован.
Поддержка конкретного сайта, приложения, UDP или клиента требует
собственной проверки. Публикация не означает production deployment.

Исходный IMAGE_BOOT_ACCEPT=FAIL из-за раннего AWG → Mihomo сохранён.
f00c93e прошёл отдельный реальный reboot; нового full-media восстановления
исправленного образа не было. Два FAT metadata bytes отличались;
полное raw SHA-совпадение отсутствовало. Это принятое исключение,
не новый PASS. [Подробности](TESTING-v1.3.0.md).
