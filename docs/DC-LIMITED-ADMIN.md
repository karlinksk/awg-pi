# Desktop Commander: ограниченные root-диагностики (v1.3.0)

Этот компонент **не нужен** для работы VPN-шлюза и **не включается автоматически**. Штатный DC остаётся непривилегированной службой пользователя; при установке/обновлении только устанавливаются два helper-файла (root:root, 0755). Installer **не** создаёт или изменяет `/etc/sudoers.d/90-awg-dc-admin`, не меняет DC `blockedCommands`, не запускает агента и не трогает сетевые политики.

## Включение только по решению владельца

1. Настроить и авторизовать обычного пользователя DC (например, `awg-dc pair`; `sudo awg-dc enable USER`). Проверить, что `~/.desktop-commander-device/device.json` принадлежит этому пользователю и имеет права 0600. **Не публиковать session/device.json.**
2. В интерактивном SSH от имени владельца выполнить `sudo /usr/local/sbin/awg-dc-admin-access enable USER`. Имя пользователя проходит ограниченную проверку; допустим только локальный непривилегированный пользователь с `/home/USER`. `visudo` проверяет политику перед атомарной установкой. Чужую policy помощник не перезаписывает.
3. **Отдельно и осознанно** разрешить `sudo` в собственных настройках Desktop Commander, если он входит в `blockedCommands`. Это расширяет доступность команды для всего агента, поэтому сначала проверить существующие `sudoers`/NOPASSWD-разрешения этого пользователя. Ни installer, ни helper не снимают запрет автоматически.
4. Проверить из DC: `sudo -n /usr/local/sbin/awg-dc-admin status` и `sudo -n /usr/local/sbin/awg-dc-admin stage18`. Только перечисленные варианты без произвольных параметров разрешены правилами.

`sudoers` предоставляет ровно пять команд с точными аргументами: `status`, `services`, `network`, `versions`, `stage18`; не предоставляет shell, редактор файлов, произвольную программу или `ALL`. Helper использует фиксированные пути/argv, очищенное окружение, ограниченные тайм-ауты, не читает/публикует ключи, URL подписок и токены. `stage18` проверяет права root, SHA-256 и версию двух заранее загруженных бинарников; при непроверенном кэше — `FAIL`, а не скачивание или исправление. Остальные действия диагностические, без изменения маршрутов, служб и профилей.

**Ограничение:** это не универсальный root API и не способ управлять тестами с намеренным отключением транспорта. Такие действия требуют отдельного ручного разрешения и конкретного сценария с откатом.

## Отключение

В интерактивном SSH:

```bash
sudo /usr/local/sbin/awg-dc-admin-access disable USER
sudo /usr/local/sbin/awg-dc-admin-access status USER
```

Команда удаляет **только** собственную точно совпадающую запись `/etc/sudoers.d/90-awg-dc-admin`; чужую политику не затрагивает. При желании дополнительно вернуть `sudo` в DC `blockedCommands`. Перезапуск VPN или маршрутизатора не требуется. При штатном upgrade первоначальный режим и существующее opt-in разрешение сохраняются, новую привилегию без согласия installer не добавляет.

## Приёмка

- Без opt-in: никаких новых sudoers, прежний DC без root.
- После opt-in: пять точных разрешений возвращают только фиксированные безопасные статусы, произвольное действие/аргументы отклоняются.
- Кэш Stage18: правильные файлы/права/хеши/версии = PASS, иначе FAIL.
- После revoke: `sudo -n ...` без иных независимо предоставленных прав должен получить отказ.
- SSH, SSTP, DNS, AWG/Mihomo/Xray, Hot Pool и READY не меняются; кнопки запуска/пароля/логов не добавляются.
- Не засчитывать реальные LAN, TUN, отказ, reboot без аппаратной проверки.

ПРЕДУПРЕЖДЕНИЕ: безопасность системы дополнительно зависит от **всех** имеющихся ранее sudoers-прав пользователя, не только от этой policy; ограничение `blockedCommands` — лишь дополнительный барьер Desktop Commander, а не системная граница привилегий.
