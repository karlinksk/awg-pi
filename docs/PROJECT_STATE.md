## 2. Принятая архитектура

- Режимы: **Selective = FAIL-OPEN**, **MikroTik Transit / Backup VPN = FAIL-CLOSED**. Transit не пропускает выбранный трафик DIRECT при отсутствии рабочего VPN; разрешён явно определённый статус `NO_WORKING_TRANSPORT`.
- **Mihomo — основной транспорт**, **AWG — резерв**, когда его рабочий профиль действительно настроен. Не считать AWG готовым только из-за установленного движка; не пытаться активировать незаполненный профиль.
- Mihomo-кандидаты проверяются по поддерживаемым типам транспорта/протокола, а не только VLESS. Hot Pool/READY: HTTPS-проверки OpenAI API и ChatGPT плюс **один реальный 24-кадровый декод YouTube**. Удалённая первичная HTTP/Range-проверка YouTube не должна снова становиться пропускным критерием. **Браузерная проверка ChatGPT не нужна.**
- Hot Pool работает изолированно от активной ноды и её сервера/алиасов; SHADOW-тесты не должны прерывать live-соединение. Успех локального proxy **не равен** успеху `mihomo0`/TUN и **не равен** передаче трафика клиента LAN. READY и переключение требуют адекватных postcheck и rollback, предотвращения колебаний.
- AUTO/резервирование транспорта: консервативная политика, не подменять приоритеты переключениями «ради скорости». Возврат с AWG на Mihomo не включать самовольно; окончательная автоматическая политика возврата требует явного подтверждения и практического теста (в прежних обсуждениях были разные варианты).
- DNS остаётся независим от VPN (DoH на MikroTik по принятой схеме). Без согласования не внедрять DNS hijack, fake-IP, SNI sniffing, изменения DNS роутера.
- При испытаниях сохранять приоритетный административный канал **MikroTik SSTP** и SSH, доступ к LAN. IP нового тестируемого VPN-сервера должен идти DIRECT, не через SSTP/другой VPN. **MikroTik, действующую microSD и продуктивный шлюз без отдельного разрешения не трогать.**
- Подписки/ключи/токены не копировать в публичный GitHub или диагностический вывод.
