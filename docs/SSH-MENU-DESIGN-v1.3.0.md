# Единый дизайн SSH-меню AWG Pi Gateway v1.3.0

Стиль всех диалогов awg-menu задаётся одним процессным файлом DIALOGRC,
который создаёт сам src/awg-menu, удаляя его при выходе. Не меняются
пользовательский ~/.dialogrc, /etc/dialogrc, системная локаль или настройки
терминала. Чистая установка и обновление получают стиль вместе с src/awg-menu.

## Принципы

- Тёмно-синий внешний фон, светлая голубая панель и тёмная выделенная строка.
- Единый вид заголовков, рамок, кнопок, строк ввода, поиска и справки.
- Описание каждой команды остаётся в --item-help (появляется при выборе
  строки). Стандартный Debian dialog не обеспечивает постоянные
  многострочные подписи под каждым пунктом, как на концептуальном макете;
  для точного соответствия потребовалась бы новая TUI-библиотека, что
  не входит в release gate v1.3.0.
- Исходное поведение клавиш, Esc/Cancel, числовые теги, подтверждения,
  размеры для SSH 70×22 и ограничение габаритов по TTY сохранены.
- Настройки AUTO/FIXED, ручной Xray, Hot Pool, SSH, DNS и транспортная
  маршрутизация не зависят от цветовой схемы.
- «Резервирование узлов Mihomo»: пять рабочих пунктов; выбор ноды остаётся
  только в основном разделе «Точка выхода / узел». Xray AUTO — внутри
  настроек AUTO; прежний standby-repair сохранён в «Расширенные /
  восстановление»; общий выключатель ручного Xray не добавляется.
- Основное меню «Mihomo» содержит только 1–5 и «Назад»: отдельный пункт
  «Xray VLESS: диагностика» перенесён внутрь «Расширенные / восстановление»
  (там номер 6). Состояние Xray, список VLESS, независимые HTTPS-probe и
  локальная служба остаются доступны. Живой ручной переход Mihomo↔Xray
  по-прежнему выполняется из «Точка выхода Mihomo / Xray».

## Проверки

Синтаксис Bash; адресные тесты test_menu_dialog_theme.py,
test_menu_ux.py, test_menu_auto_strategy.py, test_xray_auto_menu.py,
test_xray_auto_release_menu.py, test_dc_menu_placement.py.
На Debian с dialog выполняется изолированный PTY-smoke с настоящим виджетом.
Это не проверка LAN, reboot или чистой установки.


## Breadcrumb navigation (SSH/dialog)

Для всех окон, кроме «Главное меню», заголовок рамки показывает путь
«Главная › VPN › Mihomo › Резервирование › AUTO» — по фактическому стеку
функций Bash. Последний уровень является текущим экраном и не дублируется.
Навигационный путь для диагностики, просмотра текста, подтверждений и ввода
обеспечивается централизованно общей функцией dialog().
В небольших терминалах отображается «Главная › … › текущий раздел»,
чтобы не занимать место у списка нод. История не хранится глобально:
Esc/Cancel не оставляет устаревший путь. Крошки — это навигационный
ориентир, не ссылки; возврат штатными клавишами или пунктом «Назад».
Проверяется отдельным tests/test_menu_breadcrumbs.py и PTY 70×22.


## Навигация транспорта без дублирующего мастера

Из «VPN-маршрутизация [TRANSIT]» удалён прежний пункт 5
«Добавить / настроить транспорт»; пункты «Активный транспорт» и
«Политика выбора транспорта» сдвинуты на 5 и 6. Для SELECTIVE
аналогично удалён прежний пункт 6, остальные — 6 и 7.
Мастер был тонкой развилкой между существующими конфигураторами.
Профили AWG добавляются через «Конфигурация AmneziaWG» и awg-first-run,
а Mihomo — через «Mihomo → Подписка / источник», в том числе после
чистой установки без заранее настроенных подписок. Оба движка по-прежнему
обязательны при установке, независимо от наличия профилей.
Логика выбора активного транспорта и автоматического резервирования,
включая FAIL-OPEN/FAIL-CLOSED, не менялась.


## Вертикальное размещение списков пунктов

Нативный Debian dialog автоматически располагает элементы меню у верхней
границы его собственной области и не поддерживает опцию вертикального
центрирования строк в большой фиксированной рамке. Для компактных меню
общая функция dialog() уменьшает высоту окна до количества видимых
элементов плюс переносы описания и служебные строки. В результате
**весь диалог располагается по центру SSH-терминала**, и под коротким
списком не остаётся большой пустой области. Пункты внутри списка
по-прежнему имеют стандартное выравнивание по левому краю.

Высота не увеличивается относительно исходной; широкие каталоги
нод сохраняют прокрутку, объясняющие тексты учитываются при переносе,
экран не становится меньше 12 строк, пользовательские Cancel/Enter,
теги, help и маршрутизация не затрагиваются. Фиктивные интерактивные
«пустые пункты» не добавляются. Это безопасный компромисс native dialog,
а не пиксельно точное центрирование списка внутри прежней большой рамки.


## Читаемость статусов в диагностике и окнах результатов

На светло-голубом фоне штатный Debian dialog выводит статусные значения
чёрным, но некоторые SSH-клиенты выполняют собственную подсветку слов
OK / yes ярко-зелёным цветом. Такая подсветка не управляется
палитрой AWG. Чтобы результат был читаем в разных терминалах, общие
текстовые окна результатов показывают ИСПРАВНО вместо отдельных
слов OK и ДА вместо значений yes после разделителей : / =.
Подмена производится только во временной копии для просмотра с
правами 0600, которая удаляется после закрытия окна. Сырой вывод,
диагностические отчёты и параметры сети сохраняются без изменений.
Машинные статусы NETWORK_OK и другие идентификаторы не заменяются.

Проверяется tests/test_menu_status_contrast.py: вывод сообщений,
безопасность временного файла, сохранение оригинала, отсутствие
подмены машинных идентификаторов. Цветовая подсветка IP-адресов,
если она включена в SSH-клиенте, на стороне Pi не регулируется.


## Русские подписи системных кнопок

Все диалоги используют штатные `--ok-label`, `--cancel-label`,
`--yes-label`, `--no-label`, `--exit-label` (`ОК`, `Отмена`,
`Да`, `Нет`, `Закрыть`). Эти параметры меняют лишь подписи, но не
коды возврата, Enter/Esc или подтверждения. Технические названия
Mihomo, Xray, AUTO, FIXED и сетевые идентификаторы не переводятся.

Регрессия транспорта: `check_mihomo` проверяет Pi-bound TUN HTTPS
уже в ожидании healthy; отрицательный тест правильно принимает отказ
«Target transport is unhealthy; state unchanged», а не ожидает только
позднюю отдельную ветку TUN. Это обновление тестового ожидания, а не
ослабление проверки или изменение FAIL-CLOSED.


## Один источник количества нод во всех окнах

После импорта список подписки отображает все профили по порядку
в исходном provider YAML, без сокрытия failed/untested Xray или Mihomo.
Статусы раздельные: Mihomo работает, Mihomo отказ, Mihomo не проверен;
Xray HTTPS OK (изолированный proxy, НЕ TUN), Xray не проверен/ошибка;
неподдерживаемый формат и дублирующиеся имена видимы, но не могут
быть выбраны. Счётчик «Показано N из M» означает количество отображаемых
профилей при текущих поисковых, региональных и протокольных фильтрах,
а не количество работоспособных узлов.

Каталог выбора точки выхода и FIXED-редактор используют один engine-aware
picker на той же свежей подписке. Для текущей FIXED-цепочки без
экспериментального сертификата разрешаются только живые Mihomo; все
прочие профили показываются для прозрачности, но редактор не меняет
политику по нажатию на них. Ручная смена Mihomo/Xray остаётся защищена
отдельной network/TUN preflight и rollback. Фильтр «Только Европа» всё
ещё скрывает Xray, потому что для них пока нет независимой проверки
фактической страны выхода. Нельзя приравнивать имя страны к Exit GeoIP.
