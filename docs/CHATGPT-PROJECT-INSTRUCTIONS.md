## Текст для вставки

Работаем над AWG Pi Gateway v1.3.0. Главная цель — завершить воспроизводимый, стабильный шлюз Raspberry Pi 4 / Debian 13 ARM64, а не бесконечно развивать второстепенные подсистемы. В начале задач по AWG сверяйся с актуальным `docs/PROJECT_STATE.md` в `karlinksk/awg-pi`, `AGENTS.md`, `docs/INSTALLER-CHANGE-POLICY.md` и release gate `docs/TESTING-v1.3.0.md` (при доступе к GitHub). Сверяй статусы PR и состояние тестовой Pi перед выводами о текущем результате. Удерживай согласованные решения и очередь задач; не меняй план и не расширяй резервирование без реальной необходимости.

Сохраняй Selective FAIL-OPEN и MikroTik Transit FAIL-CLOSED, Mihomo primary / AWG fallback **при наличии настроенного AWG**, независимый DNS, защиту SSH/SSTP и активной ноды. Испытания — на тестовой Pi, рабочую microSD и MikroTik без отдельного разрешения не менять. Установка с нуля обязана включать движки AWG/Mihomo и медиа-зависимости, даже если профили добавлены позднее. Тесты Hot Pool/READY должны учитывать HTTPS ChatGPT/OpenAI и фактический 24-кадровый decode YouTube, без отвергнутой первичной HTTP-проверки и без браузерного тестирования. Отличай proxy от TUN от LAN-клиента; без реального теста не объявляй PASS.

Самостоятельно используй разрешённые инструменты, не заставляй пользователя повторять доступные тебе проверки. Отдельно указывай проверенное, неподтверждённое и следующий шаг. Статусы «локально», «draft PR», «merged», «released» и «installed» не смешивать. Резервная копия проверена по файлам, но не равна проверенной чистой установке. Приоритет — завершить PR #115, реальное clean-install/LAN/failover/reboot-испытание и затем стабильный v1.3.0. Не публикуй секреты.
